# 蒼の境界の製品版に向けた開発計画

完全クリアまで遊べる小規模なオリジナル作品を目標にする。シナリオの量、戦術的な選択肢、読みやすさ、操作と演出の一貫性を、章を通して評価する。ビルドごとに初回の圧縮転送量2 MB、画像と音声の各500 KBを目安として計測する。

| 段階 | プレイヤー体験 | 完了の判断 |
| --- | --- | --- |
| 1. 導入戦 | 峠で移動・攻撃を学び、勝敗と再戦を体験する | 実ブラウザで両結果と再戦を確認 |
| 2. 戦闘の選択 | 能力値・低木・反撃を比較して、攻撃の是非を決める | 予告、先制、反撃、撃破でHPの整合性を検証 |
| 3. 章進行 | 勝利後に次章へ進み、護衛など異なる条件に挑戦する | 章移行と途中再開、各勝利・敗北条件を通しで検証 |
| 4. 編成と成長 | 装備や育成を章間で選び、編成の違いが戦術に反映される | 複数の編成で序盤から終盤までクリアできることを確認 |
| 5. リリース品質 | メニュー、導入、終章、戦闘演出、音を一貫した体験として仕上げる | 全章、セーブ復元、実機の操作性、聴感、読み込み時間を確認 |

## 段階2の実装

攻撃・守備・耐術・射程をユニットごとに設定した。斬撃は守備、術撃は耐術で軽減され、低木は被ダメージをさらに1減らす。最低ダメージは1。生き残ったユニットは射程と遮蔽が許す場合に反撃し、反撃で攻撃側が倒れる場合も勝敗を更新する。攻撃予告・実行・敵AIは同じ計算を使う。

攻撃を選ぶと双方のHPの変化を確認でき、キャンセルすると行動を消費しない。専用の交戦表示は戦場と同じ生成アトラスからスプライトを拡大し、斬撃と術撃、命中時のHP更新、反撃を順に表示する。

本番のPages用ビルドはgzip換算で345,650バイト。内訳はJavaScript 340,093、CSS 3,469、HTML 2,088バイト。画像・音声ファイルは0バイト。

## 段階3の実装

第1章を勝ち抜くと「渡し守の灯」へ進める。第2章では川の2本の橋から経路を選び、攻撃できない渡し守ナギを東岸の灯火台まで護衛する。ナギが到着すれば勝利し、ナギが倒れれば敗北する。ナギは最大2マス移動でき、敵AIはナギへの攻撃を優先候補に含める。

完了した味方の行動、敵フェイズ全体の終了、章の切り替え、勝敗をブラウザに自動保存する。再読み込み時には選択中のユニット、位置、HP、行動済みフラグを復元する。破損した保存や未知のバージョンは初期状態に戻る。章の開始時は部隊のHPを回復し、各章の初期配置で始まる。

Pages用ビルドのgzip換算は348,138バイト。内訳はJavaScript 342,313、CSS 3,582、HTML 2,243バイト。地形とナギは既存の生成アトラスに追加し、画像・音声ファイルは0バイト。

## 段階4の実装

第1章と第2章の間に出撃前の編成を追加した。アステルは攻撃を1下げて守備を1・耐術を2上げる盾を選べる。リナは耐術を1下げて攻撃を2上げる杖を選べる。共通の訓練枠ではアステルの最大HP +2かリナの攻撃 +1を選べる。どちらの装備も標準品を選べ、訓練せず出撃することもできる。

編成で増減する数値を出撃前に確認でき、出撃後のステータス、戦闘予告、先制と反撃、敵AIに反映される。編成は選択中にも保存され、第2章の再戦時に維持される。旧版の保存は標準装備、訓練なしで読み込む。

Pages用ビルドのgzip換算は350,024バイト。内訳はJavaScript 343,558、CSS 3,923、HTML 2,543バイト。画像・音声ファイルは0バイト。

## ビジュアルの仕上げ

峠と川辺には新規生成の章別パノラマを使い、WebPに圧縮した。交戦の背景と編成の見出しにも同じ絵を再利用する。戦場のタイルには地形ごとの陰影と細部を追加し、移動、攻撃、照準を点・隅の枠・色で区別する。肖像は32×32の手続き描画とし、ユニットの詳細、部隊一覧、編成に表示する。戦場とユニットの拡大は整数倍率を維持する。

Pages用ビルドの全配信物はgzip換算で485,443バイト。内訳はJavaScript 345,306、CSS 4,570、HTML 2,589、章別背景132,978バイト。音声ファイルは0バイト。新規の第1章を開く時点では峠の背景のみ読み込み、合計407,119バイト。川辺の背景は編成を開くか第2章を表示した時に読み込む。

表示はデスクトップ1280×720と1280×900、モバイル相当390・375・320 CSSピクセル幅をChromiumで確認した。実機・公開先のPagesでの検証と、別章への美術展開は引き続き残る。

## 携帯機世代のドット絵に合わせた更新

GBA期の戦略RPGを参考に、草地・石垣・水面の色を分け、青と金の縁取りと明るい紙色で画面を統一した。交戦にはマップ駒とは別の44×44ピクセルの横向きスプライトを実行時に描画し、待機、構え、攻撃、被弾を切り替える。戦闘背景も峠は草地、川辺は橋の床板として手続き描画する。攻撃を確定する前に双方の肖像を確認できる。絵とキャラクターは『蒼の境界』向けに制作した。

Pages用ビルドの全配信物はgzip換算で488,493バイト。画像ファイルは前段階と同じ132,978バイト、音声ファイルは0バイト。新規の第1章を開く時点は410,169バイト。

## 戦場と交戦の切り替え

GBA版の公開キャプチャを比較し、盤面に近い地形表示、青い移動範囲と橙の攻撃表示、横方向の交戦とHPの読みやすさを参考にした。今回の素材は、蒼の境界の登場人物と地形に合わせて描画している。 [烈火の剣の戦場キャプチャ](https://raw.githubusercontent.com/libretro-thumbnails/Nintendo_-_Game_Boy_Advance/master/Named_Snaps/Fire%20Emblem%20-%20Rekka%20no%20Ken%20%28Japan%29.png) · [聖魔の光石の任天堂製品ページ](https://www.nintendo.com/en-gb/Games/Game-Boy-Advance/Fire-Emblem-The-Sacred-Stones-266749.html)

交戦時は盤面を専用画面に切り替える。攻撃者が間合いを詰める動き、被弾の数字、段階的に減るHPゲージ、撃破後の退場を表示してから戦場へ戻る。足元の描画は戦うマスに応じて草地・古道・橋の3種類。攻撃前にも双方の肖像と装備を確認でき、カーソル位置の地形を盤面直下に表示する。

Pages用ビルドの全配信物はgzip換算で490,111バイト。新規第1章の読み込みは411,787バイト。画像・音声ファイルの追加はない。

## 肖像の改善

アステル、リナ、ナギ、鉄牙、灰の術士の肖像を描き直し、配置と顔の大きさを揃えた。1人は64×64ピクセルで、5人分を320×64の透過WebPにまとめた。戦況、編成、戦闘予告、交戦のHP欄で共用し、小さい欄は32ピクセルで表示する。画像を取得できない場合は手続き描画の肖像が表示される。

肖像の追加は10,320バイト。Pages用ビルドの全配信物はgzip換算で500,776バイト、初回の第1章は422,452バイト。画像合計は143,298バイト、音声ファイルは0バイト。


## 終章とエンディング

第2章クリア後に「夜明けの火守」へ進む。前章で選んだ装備と訓練を引き継ぎ、HPは全快で出撃する。敵フェイズ終了時に味方が見張り台を占めていれば防衛が1回進む。2回連続で守れば勝利し、エンディングを読める。空けたまま敵フェイズを終えると連続回数が0に戻る。防衛の途中と全章クリアの状態を保存する。旧セーブの第2章勝利からも終章に進める。
