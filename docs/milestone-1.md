# マイルストーン1　古い峠の防衛線

## 着手時の確認

基準は `d5a498d`。取得時点で8列×6行の戦場、味方2人と敵2人、敵AI、勝敗・再戦、合成音声が実装済みだった。CloudのChromiumで基準のPlaywright 2件、Vitest 6件が通過した。

移動表示は始点と終点の直線補間だったため、合法な移動先でも途中で石垣を横切って見えた。各ユニットの射程が同じで、攻撃結果が出る前に勝敗画面が重なる場合があった。盤面の表示倍率はコンテナに連続追従しており、キーボード操作、敗北までのブラウザ検証、本番サブパスでのブラウザ検証が未整備だった。

## 今回の縦切り

- 草地、連続した道、石垣、低木、4人の戦闘スプライトを共通パレットで描き、1枚の生成アトラスに集約。青と赤のHPバー、武器と服装のシルエットで陣営と役割を識別できる。
- 盤面を176×136の論理ピクセルで描画し、表示はコンテナに収まる最大の整数倍率。戦場のすぐ下にターン終了ボタンを置いた。
- ルールの探索結果を経路プレビューと移動アニメーションで共有。橙の点は射程、橙の枠は攻撃可能な敵。騎士と略奪兵は隣接攻撃、術士は最長2マス。石垣は移動と術の経路を遮る。
- 敵に照準を合わせるとHPと攻撃結果を予告。斬撃の踏み込み、術弾、命中時の閃光・ダメージ値・交戦欄、撃破、フェイズ表示、勝敗・再戦までつなげた。
- 矢印キーとEnter、マウス、タップで操作できる。Web Audioで主旋律と低音、選択・移動・斬撃・被弾・ターン・勝敗の短い音を合成し、消音時は予約音と再生中の音を止める。

## 容量実測

`npm run build` の容量スクリプトによる測定。gzipレベル9で圧縮した静的ファイルのバイト数で、HTTPヘッダーは含まない。着手時は通常ビルド、完成時はPages用サブパスを指定してビルドした。

| 項目 | 着手時の生バイト | 着手時のgzip | 完成時の生バイト | 完成時のgzip |
| --- | ---: | ---: | ---: | ---: |
| JavaScript | 1,223,816 | 336,826 | 1,228,278 | 338,808 |
| CSS | 6,742 | 2,404 | 7,563 | 2,595 |
| HTML | 3,597 | 1,750 | 3,842 | 1,827 |
| 画像・音声ファイル | 0 | 0 | 0 | 0 |
| **合計** | **1,234,155** | **340,980** | **1,239,683** | **343,230** |

指定対象のJS・CSS・画像・音声を合計すると341,403バイト。HTMLを含めても2 MB以内。Viteは圧縮前のJSチャンクが500 kBを超えるという警告を出す。配信量の上限は既存の容量スクリプトで継続して検査する。

## Cloudでの検証

- Vitest 8件。移動制限、壁を回る経路、攻撃、術の射程・遮蔽、ターン切替、敵AI、勝敗、再戦を検証した。
- Chromium 155のPlaywright 3件。本番ビルドを `/tactical-rpg-starter/` で開き、同じサブパスからJSとCSSを取得。操作と内部状態で勝利・敗北・再戦、攻撃予告、タップ、キーボード、音の生成と消音を確認した。盤面は390・375 CSSピクセル幅で2倍、320幅で1倍を検証した。
- スクリーンショットは `test-results/` に保存。戦闘開始、移動経路、命中、勝利、敗北、モバイル表示を記録した。CIも同じ本番サブパスでPlaywrightを実行する。
- 実環境のGitHub Pagesへの公開、実機・他ブラウザ、音の聴感は未検証。ローカルのVite Previewで配信構成を確認した。
